## 0. 题目与研究问题（写在封面/摘要，先定调）

- **一句话研究问题**：个人投资者面对海量行情与事件信息，缺一套**可解释、可回溯、能自我纠偏**的仓位决策框架；现有平台要么只展示不决策，要么决策是黑箱不可复盘。
- **一句话创新点**：在事件驱动投研平台之上，提出并实现一个**决策闭环**——以温度/方向/周期/晋级率四维输入经 `derive_position` 推导 5–95 仓位，并用**刻度校准**（`calibration.py` 以历史回测反推 `CYCLE_ADJ` 修正各周期仓位刻度，T1 阶段只出建议不自动改规则以避过拟合）形成可自纠偏、可解释的决策层。
- **一句话贡献**：① 一个覆盖行情/事件/回测/持仓/决策全链路的事件驱动平台；② 一套"可解释 + 可自纠偏"的仓位推导方法（算法 + 校准 + 回测验证）。

## 第 5 章 创新点：决策闭环与刻度校准（★重点章，写最细）

### 5.1 问题提出：为何需要"可解释 + 可自纠偏"的仓位决策
- 写作动机（答辩必问）：① 黑箱模型不可复盘、错了不知错在哪；② 静态规则在不同情绪周期下刻度会偏（熊市满仓刻度、牛市空仓刻度都错）；③ 小样本下盲目"自动调参"=过拟合。
- 雷区：**5.1 必须写透"为什么是你做的、解决什么别人没解决的"**，不要堆代码。

### 5.2 决策闭环：`derive_position` 与落盘
- **引用真实 `modules/decision.py`**：
  - `derive_position(temp, score=None, bias=None, cycle_name=None, overall_promo=None, ...)`（line 98）——温度基准 + 方向±8 + 周期调整 + 晋级率，`clamp 5~95`；`overall_promo=None` 时不加不减（缺数据≠看空，这是关键设计选择）。
  - 落盘：`build_snapshot`(461) → `save_snapshot`(570) → `data/daily_snapshot.json`（最新，首页直读）+ `data/snapshots/YYYY-MM-DD.json`（归档回测源）；`load_snapshot`(598)、`archive_path`(45)、`list_archive_dates`(63)、`is_stale`(628)。
- **可解释性证据（重点！）**：`position` 字段含 `reasons` 列表，逐条给出推导依据，例如真实样本：
  - `"市场温度 24 作为基准仓位"`
  - `"次日方向「中性」加仓 0%"`
  - `"梯队断档（晋级率<20%）：减仓 6%"`
  - `"事件驱动催化：加仓 2%"`
  → 这正是"可解释"的落地：每个仓位建议都能回溯到显式规则，而非模型黑箱输出。
- 图：**决策闭环流程图**（输入四维 → derive_position → clamp → 落盘/归档 → 预测追踪 → 校准反馈）；**温度 vs 仓位散点图**（真实数据，见第 12 节 `fig_temp_pos.html`）。
- 表：决策因子对照表（因子 → 取值来源 → 对仓位的作用方向）。

### 5.3 刻度校准：`calibration.py` 与三条铁律
- **引用真实 `modules/calibration.py`**：
  - 校准思路：用回测反推 `CYCLE_ADJ` 修正各周期仓位刻度；`_suggest_delta(avg_realized) = clamp(2 × 次日平均涨跌, ±5)`（line 73）。
  - 核心函数：`_cycles_of`(59) / `_cur_adj`(73) / `suggestions`(81) / `as_patch`(140) / `apply_patch`(162) / `verdict`(242)。
  - **三条铁律（写清，是创新点的方法论核心）**：
    1. **T1 只出建议不自动改规则**：`as_patch()` 只返回 dict，**绝不写 `decision.py`**（小样本拟合=过拟合，禁止自动落地）；
    2. **T2 有界 ±5**：任何刻度修正不超过 ±5，防剧烈漂移；
    3. **T3 小样本不表态**：`n_call<8` 不出观察行；`<20` 或 `|delta|<2` → `actionable=False`。
  - **就绪语义（关键设计细节，可放答辩利器）**：`verdict()["ready"]` = **至少有一个战术分组达到可采纳阈值**（`any_actionable`），**不是**全局 `n_call>=20`。原因：样本平摊到 4 组（进攻/分化/修复/防守），全局到 20 往往无单组到 20，否则会"误报可校准"。对应单测 `test_verdict_spread_not_ready`。
- 图：**校准机制框图**（回测样本 → suggest_delta → as_patch(只建议) → 人工/阈值采纳 → CYCLE_ADJ 落地）；**校准前后刻度对比示意表**（用真实 `suggestions()` 输出，若样本不足则给出"机制示意 + 真实 guarded 输出"）。
- 雷区：要说清"校准≠自动调参训练模型"，是**规则刻度的有界修正**，且默认 conservative（只建议）。

### 5.4 预测 vs 实际回测：闭环可验证性
- **引用真实 `modules/decision_track.py`**：
  - `record_prediction`(54) 每日落盘一条预测（挂钩 daily_snapshot 落盘后）；
  - `score_predictions`(404) 联网拉次日上证 000001 涨跌判方向命中；
  - `summary`(125)/`chart_data`(144) 纯本地、断网优雅降级；
  - `by_cycle`(190)/`by_group`(242) 六阶段→四大战术分组（进攻/分化/修复/防守，单阶段样本稀疏故归并），带"平均建议仓位 vs 次日平均实际"；`by_event`(286) 事件边；`last_scored_date`(275)。
  - 命中率配色**不套红涨绿跌**（>=60 绿 / <40 红 / 中间黄），语义是"可不可信"。
- 图：**预测 vs 实际双轴图**（`chart_data` 的 plotly 双轴，可直接用）。
- 雷区：命中率语义是"方向可信度"，不是"收益"。

- 收束：决策闭环（可解释）+ 刻度校准（可自纠偏）+ 预测追踪（可验证）= 三位一体的"可解释仓位推导"。
