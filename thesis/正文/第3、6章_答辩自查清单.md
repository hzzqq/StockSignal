# 第 3、6 章答辩自查清单（模拟评审）

> 用法：按"评审最可能追问"排序，每问给一句话应答要点与证据定位。答辩前通读一遍，被问到能直接指出节号/文件即可。数字以 2026-10-28 守卫通过的版本为准。

## 第 3 章 需求分析与总体设计

### 3.3 总体架构
- **Q 为什么不用微服务？** 一人多机自用系统，复杂度收益不匹配；四层单体 + JSON 信封契约已把界面变更与算法变更解耦，3.6 节的设计模式（策略/单例/工厂）解决了扩展性问题。
- **Q 层间契约怎么强制，靠自觉吗？** 不靠自觉——89 个 REST 端点有契约测试层锁死信封结构（6.1 节），后端改字段前端静默白屏的事故被测试拦截。
- **Q 72 个 Streamlit 页面单体会慢吗？** 页面按需加载 + `safe_fragment` 局部刷新禁整页 rerun（3.2 实时性），首帧主题注入避免样式抖动；证据见 6.1 冒烟层对全部页面的启动测试。
- **Q 逻辑层为什么必须独立于 streamlit？** 106 个纯逻辑模块可独立编译与单测，是 4394 个测试能跑在无 UI 环境的前提——这是分层测试体系（6.1）能成立的架构基础。

### 3.4 数据库设计
- **Q 为什么用 SQLite 不用 PostgreSQL？** 单机单写场景，SQLite 零运维且够用；并发写在 Flask 侧经蓝图串行化，6.1 数据隔离层的独立库探针（`ss_probe`）验证了不锁生产库。
- **Q 三份产物（最新/归档/对账）为什么分开？** 读写分离：最新文件服务当日查询，归档保证不可变审计，对账表支撑预测追踪（6.2 的次日对账依赖它）。
- **Q 数据坏了怎么办？** 两级还原链（.bak + git 追踪镜像），变更一律先 --dry-run（3.5.2）；守卫 `test_no_silent_write_swallow` 拦截静默写失败。

### 3.5 数据底座（创新点章的支撑设计）
- **Q 单一真理源靠什么执行？** AST 静态守卫（6.5）：`derive_position`、`CYCLE_ADJ`、信号目录、导航注册表等 5 处均有守卫锁定，改规则只改一处，抄路径/绕过单源会被测试拒绝。
- **Q CSV 和 JSON 双源为什么不合并？** 重叠段（2009-11 起 4084 天）老板拍板"维持 CSV 现状"以保护已钉论文口径（49.1%/4092），JSON 独有段（2007-2009）单独保留；合并会改变历史温度序列——3.5.3 的"稀疏签名守卫"就是防止好心修复破坏口径。
- **Q "诚实数据语义"具体指什么？** 四条：数据不足即 `unavailable` 不补零、`clear_cache` 报真实删除行数、变更先 --dry-run、.bak 可还原；答辩时引用 3.2 非功能需求与 6.5/6.6 的守卫验证。

## 第 6 章 系统测试与质量保障

### 6.1 测试分层体系
- **Q 4394 个测试会不会是凑数？** 五层各有分工：冒烟（72 页可启动）、单元（106 纯逻辑模块）、契约（89 端点信封）、数据隔离（探针库）、静态守卫（77 文件）；且 6.6 变异验证证明关键测试非假绿——注入缺陷测试必须变红。
- **Q 测试代码比 0.64:1 怎么解读？** 405 个测试文件 5.7 万行对 106 个纯逻辑模块——重点不在比值，在"每类设计承诺都有对应测试层"（3.2 → 6.1 的映射表）。

### 6.5 AST 守卫体系
- **Q 77 个守卫的维护成本？** 守卫是测试文件，随守卫清单运行，无独立运维；新增守卫必须过 6.6 的负向验证（注入即红）才准入。
- **Q 静态解析会不会误报？** 守卫只做"存在性/结构"断言（如 CYCLE_ADJ 只允许一处赋值），不做语义推断；被拦案例（2-3 个）均为真实回归，无一例误报误伤。
- **Q 举例一个守卫拦住的真实事故？** 静默失败分诊：119 处 `except: pass` 实测（48 文件），36 处高危吞掉写盘/取数失败——如体检扫描页自选股取数失败扫描静默缩水、两融背离信号静默消失；修复后守卫防复发。

### 6.6 变异验证
- **Q 为什么不用 mutmut 全自动变异？** 人工注入选的是"最可能假绿"的守卫（平盘口径、静默失败），成本收益最优；全量自动化列为 7.3 未来工作（自动化变异测试条目）。
- **Q 变异验证和普通测试的区别？** 普通测试验证"实现对不对"，变异验证验证"测试本身有没有效"——测的是测试。

### 6.8 大规模回测
- **Q 4092 日回测怎么防前视偏差？** 全程 T-1 日状态决定 T 日仓位的因果纪律；5.4.3 组合模拟（4124 日）同样复用该纪律与 `locate_cycle` 判定函数，脚本可一键复现。
- **Q 用全市场中位涨幅做收益代理合理吗？** 不等于可投资指数——已在 5.4.3 诚实边界声明（绝对收益为负是中位数个股长期阴跌的市场特性，6.8 同口径披露）；结论取相对贡献而非绝对收益。
- **Q 有没有幸存者偏差？** 数据底座以现存 CSV 全历史为准，退市股覆盖有限——如实承认，列入未来工作；主结论（周期分化、样本外 15/15）不依赖单只股票存续。

### 5.4.3（跨章必问）
- **Q 进攻侧加仓是负贡献，那 CYCLE_ADJ 是错的吗？** 不是——它是**风险缩放器**设计：防守步长（-10）大于进攻步长（+5）的不对称设计与实证形状互相印证；有界 clamp 保证进攻侧误判代价可控（年化约 -0.5pp）；差异化刻度（分市值）已列入 7.3。
