## 〇、总览（通用版 · 30 秒电梯演讲，任何老师都能先听这段）

**一句话定位**：StockSignal 是一个 A 股「事件驱动 + 市场情绪」量化决策平台，把多源信号融成一个**可解释、防过拟合、会主动报警**的仓位决策闭环。

**解决什么问题**：散户/研究者面对海量行情、新闻、宏观数据，缺一个「把信号变成能负责的仓位建议」且**不静默出错**的系统。

**规模与工程可信度**（评委最吃的硬指标）：
- 前端 **68 个功能页**、后端 **75 个 REST 端点**、**3,197 条测试**；
- 技术栈 Streamlit（看板）+ Flask（API）+ SQLite（数据自托管，不依赖外网库）；
- 回测**严格留出评估（walk-forward 2022–2026）**，方向命中率论文锚定 **49.1%（1722/3507 样本）**；
- 前向实测 **37.5%**（15 个真实决策快照，08-31~09-21，小样本、不主动当卖点）；
- 宏观数据看板已从 6 项扩展到 **18 项**，新增 12 项全球指标（美股 / 美债 / 美元 / 汇率 / 美国宏观）。

**核心创新点（在「整合」而非单算法）**：
1. 事件因子 + 市场情绪的多源**决策闭环**（仓位 `derive_position`，可解释归因 `explain=True`）；
2. **严格留出评估**防止过拟合（49.1% 钉死，不靠样本泄漏刷分）；
3. **数据新鲜度主动报警**，根治"数据悄悄停更、系统照常给结论"的静默故障。

> 下面三段是给三位老师的**差异化版本**，通用事实不变，叙述重心与"请老师把关的问题"不同。

## 一、给刘云翔教授版（决策框架 + 改进型算法 + 强化学习/可解释）

**适配定位句**：您带学生一贯做"对经典算法改进再落地"（改进 CART、改进 RRT*、改进随机森林），StockSignal 最缺的正是一处**扎实的算法层改进**和一套**决策框架**——正好对口。

### 1. 项目简介（对刘老师强调"决策框架"）
我独立做了一个 A 股量化平台，已落地"事件因子 + 市场情绪 → 仓位决策"的**决策闭环**。现有融合用经典 GRU + 规则式仓位（`derive_position`，clamp 5~95 + 情绪周期调节 CYCLE_ADJ）。算法单拎都偏常见，缺能写进摘要的"改进点"——这正是想请您把关的。

### 2. 算法改进方向（与您对口的是 #3 / #4 / #5）
| 方向 | 替换/增强对象 | 真实结果（诚实） | 对刘老师的价值 |
|---|---|---|---|
| **#3 强化学习 RL 仓位决策** | 替代规则式 `derive_position` | Sharpe **-0.741** vs 规则式 +0.997 / +1.145；换手仅 0.026 → **边缘偏负** | 诚实的方法学反例，可框定为"边界界定"贡献 |
| **#4 SHAP/博弈论可解释融合** | 增强决策闭环归因 | 尚未实跑，是"评委友好"安全垫 | 可解释 AI 热点，评委接受度高 |
| **#5 改进型树模型/集成** | 因子筛选/融合 | 对标您改进 CART/RF 的风格 | 最贴您带教口味的"改进点" |

### 3. 刘老师会欣赏的点（项目优点）
- **决策闭环是可解释、可调参的**（不是黑箱喊买喊卖）——符合"智能决策支持系统"的研究口味；
- **已经做了诚实的负向实验**（RL 不增益），说明学生有"方法学诚实"素养，不是只会报喜；
- **系统已能跑、已测过**（3,197 测试），不是 PPT 项目。

### 4. 想请刘老师把关的具体问题
1. RL 在强信号上无增益，是"方法学反例"还是"我的奖励函数设计错了"？要不要换 reward（如最大回撤约束）重试？
2. 主改进点选 **#5 改进型树模型** 还是 **#4 SHAP 可解释** 更稳妥？哪个更容易在毕设周期内做完且能写进摘要？

## 二、给陈丽琼教授版（深度学习改进 + 严谨对比实验 + GNN/Transformer）

**适配定位句**：您的研究核心是深度学习改进（CNN/GCN/LSTM）+ 应用与对比实验，StockSignal 现有预测用经典 GRU，我想引入更先进的深度学习结构并做**严谨留出评估对比**——正好对口。

### 1. 项目简介（对陈老师强调"深度学习改进空间"）
平台已落地事件因子 + 情绪决策闭环、回测 49.1% 锚定。预测侧目前是经典 GRU；我已在 P1-QuantFactor 同口径上做了 Transformer / GNN 的 head-to-head 对比实验，结论是**诚实的**——可以据此讨论"改进点怎么写才站得住"。

### 2. 算法改进方向（与您对口的是 #1 / #2 / #4，全部已真实跑过）
| 方向 | 方法 | 真实结果（诚实口径） | 论文叙事价值 |
|---|---|---|---|
| **#1 Transformer/Attention 增强时序预测** | 替代/增强 GRU | 方向命中 **0.5130** / IC **0.0465** / ICIR **0.3796** vs GRU 0.5097/0.0374/0.3462 → **一致但小幅占优（+0.33pp / IC +24% / ICIR +10%）** | ✅ 可写"引入注意力机制提升预测"，须标注"幅度有限" |
| **#2 图神经网络 GNN 因子图编码** | 新增板块-个股传导因子 | 方向命中 **0.4948** / IC **0.0076** / ICIR **0.1047**，**三项全落后** GRU 与 Transformer | ❌ 诚实负向 → 框定为"适用边界界定" |
| **#4 SHAP 可解释** | 决策归因 | 未跑，安全垫 | 评委友好 |

### 3. 陈老师会欣赏的点（项目优点）
- **有严谨的对比实验设计**（同口径、walk-forward 留出、IC/ICIR 多指标），不是"换个网络刷个点"；
- **诚实记录负向结果**（GNN 无效），符合学术规范，也给您"指导学生做实验"的真实素材；
- **金融横向经验可迁移**（您有申能财务资金池预测背景），沟通不费劲。

### 4. 想请陈老师把关的具体问题
1. #1 的 modest 增益是否值得作为**主改进点**？要不要补更长序列 / 更多 head / 更大 hidden 验证稳健性？
2. #2 GNN 负向，是"数据集因子交互本就时序主导"还是"图该用动态/可学习边"？怎么把负向结果写成"方法学贡献"而非失败？
3. baseline 设计是否还需补一个纯 LSTM / TCN 对照，让表格更完整？

## 三、给于万钧教授版（系统设计 + 工程落地 + 大数据）

**适配定位句**：您带学生偏"区块链/大数据系统 + 工程落地"，StockSignal 是一个**已上线规模、架构清晰、工程护栏完整**的量化数据系统——可以从"系统设计与大数据处理"角度切入，算法创新交给双导师或作为子系统。

### 1. 项目简介（对于老师强调"系统规模与工程"）
StockSignal 是一个 A 股量化决策平台，**前端 68 页 + 后端 75 个 REST 端点 + 3,197 条测试**，采用 Streamlit + Flask + SQLite 自托管架构。系统的核心工程价值不在单个算法，而在：**多源数据可靠接入 → 严格留出评估防过拟合 → 数据新鲜度主动报警**这一整套**不会静默出错**的数据工程闭环。

### 2. 系统架构与规模（硬指标，评委爱看）
- **数据层**：行情 / 板块 / 宏观（已扩至 18 项，含全球）/ 事件因子 / 情绪因子，全部 SQLite 自托管；
- **计算层**：五维加权决策引擎（技术/情绪/量能/宏观/板块）+ 事件驱动策略回测；
- **服务层**：Flask 75 端点，前端 68 页 Bento 式模块化看板；
- **护栏层**：AST 不变量测试锁死工程红线（如配色不反转、数据不臆造、双机 git FF-only）；
- **诚实机制**：取不到数据返回 None 不臆造；回测严格留出，49.1% 锚死不漂。

### 3. 于老师会欣赏的点（项目优点）
- **工程完整度极高**：不是 demo，是"能跑、能测、能报警"的系统；
- **大数据/多源处理**真实存在（千万级行情、多个宏观/事件数据源）；
- **可扩展架构**：新增全球宏观指标只改一处配置即自动进看板与 API，体现系统设计功力。

### 4. 想请于老师把关的具体问题
