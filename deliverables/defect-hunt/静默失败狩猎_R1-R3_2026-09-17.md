## R1 · P1 信号目录默认值漂移

**现象**：`scripts/refresh_event_pool.py` 文档承诺「缺省用同机默认布局」，但按缺省配置**永远刷新不了**。

**证据（修前实测）**：

```
_p1_signals_dir()  →  E:/project/sj/P1-QuantFactor\data\P1\processed\signals
该目录 isdir()     →  False
真实目录           →  E:/project/sj/data/P1/processed/signals   （isdir=True，11 个文件）

refresh_event_pool_from_p1()  →  reason='no_p1_signals_dir'  refreshed=False  未写产物
```

**根因**：`modules/shepherd_ladder.py` 自己抄了一份默认路径，与 `modules/p1_signal.py` 的口径**漂移**——
两份默认值不一致，且这份指向的目录在本机根本不存在。失败只体现在返回值的 `note` 里，没有任何告警。

**修法**：删除副本，改为复用单一真理源 `discover_source_dirs()`
（优先级：`P1_PROJECT_DIR` > 候选里第一个**真实存在**的目录 > 候选首位）。
非所有者模块不再持有默认值，从根上消除再次漂移。

**修后实测**：默认目录解析为 `data/p1_signals`（存在）→ `refreshed=True`，产物正常写出。

## R2 · 候选选择口径用文件 mtime，而非数据日

**现象（指定真实 P1 目录时）**：

```
(a) 卡死：signal_rotation.json（latest_date=None）恰好 mtime 最新
    → reason='p1_signal_empty'、refreshed=False，同目录 8 个有效导出全被无视

(b) 选旧：即便跳过无效文件，mtime 序也会先选到
    signal_baseline_v39_h20.json  latest_date=2026-07-31
    而同期存在
    signal_ens_v39gru_w025_h10.json  latest_date=2026-08-14   ← 更新
```

**根因**：用「文件改动时间」当「数据新旧」。这与项目既有红线（**以数据日为准，不用 `now()`/文件时间**）
直接冲突；且「第一个候选无效就整体放弃」让单个旁路产物具备了否决全链路的能力。

**修法**：新增 `_pick_latest_valid_signal()`
- 按 `(latest_date, mtime)` 降序取第一个**有效**候选；
- 无法解析 / 字段不全的候选**跳过而不阻断**；
- 成功时把 `picked`、`skipped_bad`、`skipped_invalid` 写回 status（**留痕**，不再"小声说"）；
- **全部候选无效时仍然拒绝写入** —— 保住原设计「不用无效产物覆盖有效快照」的安全语义。

**修后实测**：选中 `signal_ens_v39gru_w025_h10.json`（2026-08-14），
note 明示「已跳过不可用候选 1 个（无法解析 0、字段不全 1）」。
返回码也做了区分：全部不可解析报 `p1_signal_corrupt`，字段不全报 `p1_signal_empty`。

## R3 · 「防静默回退」守卫自己用 skip 静音

**现象**：`tests/test_shepherd_analyze_history.py::test_analyze_history_real_history_modern_non_collapsed`
的 docstring 写着「**防止被错误重跑覆盖后静默回退**」，但它在现代段样本 <50 行时执行 `pytest.skip`。

**证据（注入退化数据实测）**：

```
备份真实 CSV（sha256 一致）
→ 把 CSV 现代段缩到 20 行
→ 该守卫输出：SKIPPED ... 现代段样本不足（20 行），疑似被错误覆盖，人工核查
→ 退出码 0，整套测试仍然全绿          ← 警报不会响
→ 还原 CSV，sha256 与原始完全一致
```

**根因**：`skip` 被用在了**告警条件**上。守卫存在的全部意义就是发现这个条件，
而它恰好在条件真正满足时把自己静音。该 CSV 在 2026-09-16 就真实退化过一次，靠人工比对 `.bak` 才还原。

**修法**：区分两种情形——
- 数据文件**整体不存在**（`data/` 被 `.gitignore` 忽略，未随仓分发）→ 允许 skip；
- 文件在、但现代段退化 → **`assert` 失败**，消息里附可操作的还原指引（从 `.bak` 还原后重跑）。

**修后实测**：同样注入退化数据 → `AssertionError`（退出码 1），警报恢复；真实 CSV 毫发无损。

**附带纠正（同族：声明与事实不符）**：`tests/test_sentiment_edge.py` 两处 docstring 声称校准件
「**随仓库发布**」且「必须存在」，而 `data/sentiment_edge_calibration.json` 实测被 `.gitignore:23`
忽略、**并未随仓分发** → 已按事实改写，并说清「缺失才可 skip，存在就必须经得起检验」。
（`modules/sentiment_edge.py` 本体缺件时本来就诚实降级为 `available=False`，无编造，无需改代码。）

## 下一轮输入（存量富矿）

1. **60+ 处 `except: pass`**（`modules/` + `pages/`）：多数是 UI 增强容错（可接受），
   需逐个判「是否吞掉了**数据/写盘**失败」。其中 `pages/20_个股分析.py` 单文件占 9 处，
   且该页已内嵌进 `24_个股研究.py`（疑似死代码，值得先确认是否还挂在导航上）。
2. **生成物契约不匹配**：喂给可视化/导出函数的 dict/DataFrame 键名或列名对不上时，
   对方常 `.get(key, 0)` 或提前 return → 产出「看起来正常」的错图。可作为 AST 契约守卫的第二批。
3. **非有限值**：`round(float('nan'))` 抛 `ValueError`、`inf` 抛 `OverflowError`，
   `if x is None` 挡不住 —— 扫一遍指标计算链的入参。
