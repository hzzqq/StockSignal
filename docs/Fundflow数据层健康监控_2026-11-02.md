# fundflow 数据层健康监控（方向 3 延续 · 2026-11-02）

## 1. 为什么做这一半

方向 3 原始落点为「fundflow/因子数据质量监控自动化」（`modules/fundflow.py` + `data/p1_signals`）。
p1_signals 半边（静态文件 SLA 体检 + 推送链 heartbeat + 定时任务）已交付；**fundflow 半边未做**。

fundflow.py 是 **实时取数层**（akshare → 东方财富，TTL 缓存 + 失败降级为空），与 p1_signals 的
静态文件范式不同，健康监控不能复用「文件 mtime/SLA」套路，需转向：

- **取数可用性**：接口是否返回非空（空 = 降级触发，页面在展示兜底而非真数据）
- **结构契约**：必需列/键是否齐全（防 akshare 列名漂移）
- **数据新鲜度**：日频序列（大盘资金流）最新日期距参考交易日是否断供
- **best-effort 登记**：业绩预告/披露日历等不稳定接口空返回只黄灯、不阻断

## 3. 设计要点

- **provider 注入**：`summarize(providers)` 接受 {名称: 无参可调用}，测试注入 fake，
  生产绑定 fundflow 真实函数；不 import fundflow 的导入期副作用（代理探测惰性，不破坏
  `test_fundflow_import` 的 R-14 回归）。
- **新鲜度口径**：参考交易日 = 今天的前一个非周末日（盘前语义：当日数据尚未产出，
  周一盘前取上周五 age=0 不误报）。宽容带：差 >3 天黄灯登记、>6 天红灯。
  A 股法定长假/春节会使参考日落在休市日、数据停在长假前（age≈7~9 误报红）——
  **已知口径限制**，遇长假人工确认，或后续接入交易日历（当前仓库无交易日历模块）。
- **北向豁免**：`northbound_history` 语义为「2024-08-16 停披露前真实值兜底」，只查结构、
  豁免新鲜度；`northbound_fund_flow` 查结构 + trade_date 新鲜度。
- **三档语义对齐 p1**：红灯 = 不可用/结构缺失/新鲜度断供（阻断，退出码 1）；
  黄灯 = best-effort 空/新鲜度边缘（登记不阻断）。

### 4.1 红灯：market_fund_flow 取数故障（真实事故，非偶发）

- 现象：`ak.stock_market_fund_flow()` 稳定抛 `ConnectionError: RemoteDisconnected`。
- 验证：CLI 内 3 次指数退避重试 + 2 次独立直连探针，全部失败（2026-11-02 00:20~00:30）。
- 影响：`get_market_fund_flow(days=30)` 按设计降级返回空 DataFrame → **页面大盘资金流
  在展示兜底提示，不是真数据**。降级路径本身健康（不红错），问题在于上游不可达。
- 处置：体检首次运行即抓到真实故障，证明该监控方向有效。上游端点故障需东财侧恢复；
  ks 侧备选（待用户拍板）：换备源（如 `stock_market_fund_flow` 的备用端点/同花顺口径）
  或红灯期间页面显式标注「数据降级」。

### 4.2 黄灯：disclosure_calendar best-effort 空

- `stock_report_disclosure` 当前返回空（接口兼容性问题），按设计黄灯登记不阻断。
- 与 fundflow.py 内注释一致（「季报/中报参数做 best-effort 映射」，接口仅稳定支持年报）。
