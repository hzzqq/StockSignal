# 组件对标说明：自研轻量组件 vs 市面组件（2026-10，T-332）

> 老板三方向之①「组件对比市面上的轻量化组件，然后优化项目组件，让用户使用更放心」的正面回答。
> 原则：只对比真实存在的组件与真实代码事实，不自夸、不贬低，优劣都写。

## 一、对标总表

| 项目自研组件 | 市面对标 | 结论 | 为什么（用户放心点） |
|---|---|---|---|
| `sf_metric` / `st.metric` 用法 | Streamlit 内置 `st.metric` | **自研约束**：强制 `delta_color`，A 股「红涨绿跌」全局语义不可反转 | 市面组件（含 Streamlit 官方）默认绿涨红跌（美股语义），直接用会让用户看反涨跌；守卫 `test_metric_delta_color` 逐页 AST 钉死 |
| `ui_kit._KIT_CSS` 统一基元 | streamlit-elements / 各类 CSS 拼贴方案 | **单源设计**：改 primitive 不迁调用点 | 多个第三方组件各自带样式体系，混用即「样式精神分裂」；单源基元保证全站视觉一致，改动成本 O(1) |
| `@st.fragment` / `safe_fragment` | streamlit-autorefresh / 整页 rerun | **局部刷新**：禁整页 rerun（守卫在） | autorefresh 触发全页重跑、状态丢失；fragment 只刷局部，行情页 5 分钟自动刷新不闪屏 |
| 诚实数据语义层 | （市面无对标——市面组件不管数据真假） | **独有**：取不到返 `status="unavailable"` 并如实说明，绝不编造、绝不默认 0；AST 造假防线抽查可视化入参 | 第三方组件「有数据就画、没数据就空/0」是常态；本项目把「不撒谎」做进组件契约（R2/R7 事故教训固化） |
| `fetch_parallel.fetch_many` 多源并发取数 | 单源 API 封装组件（如纯 akshare 封装） | **多源交叉**：akshare/新浪/东方财富/本地缓存互为备份 | 单源组件源一挂全挂；本项目源挂自动降级并如实标注「数据退化」 |
| 回测成本口径披露 | 市面回测组件/课程常见「未计费用」或隐藏假设 | **三费拆分**：佣金(双边)+滑点(买卖)+印花税(仅卖出)，默认各 0.1%，参数可调，页面明示（T-329） | 回测收益不披露成本=虚高；本项目页面直接写清费率假设，用户可自行调整复算 |
| P1 信号滞后披露 | 市面信号类产品通常不展示模型数据日期 | **滞后≥15 自然日自动警示**「建议仅供参考」（T-331）+ 推送告警（T-324） | 模型停更期间继续展示信号而不提示=误导；页面直接告诉你信号几岁了 |
| 六维排雷闸门 | 市面选股组件多为「只荐不排雷」 | **二道闸**：ST/高商誉/减持/诉讼硬红旗直接踢出推荐池（T-245），排雷不可得如实标注「未经排雷」 | 只报收益不报风险的荐股是半成品；排雷前置是本项目的结构化差异 |
| A4 事件标注层（本轮 R9） | 题材类产品（题材猎手等）的事件性质人工标注 | **透明词表标注**：hard_logic（硬逻辑/题材炒作，命中词即证据可溯源）+ horizon（由信号模型 horizon 字段如实映射），命中不足一律 unavailable | 市面「题材/硬逻辑」多为编辑人工打标（黑箱）；本项目规则透明、证据可查、分不出就明说分不出 |
| 零第三方 UI 组件依赖 | — | **依赖面**：仅 streamlit 本体 + pandas 等基础库，无 pip 级 UI 组件 | 第三方组件随 pip 升级破坏页面是 Streamlit 生态常见事故；本项目 UI 自持，升级不受制于人 |

## 二、诚实边界（自研不如市面的地方，如实写）

- **无拖拽式 dashboard**：streamlit-elements / gradio 的自由布局能力本项目没有，页面结构是固定网格；
- **图表交互**：内置图表为轻量封装，缩放/框选等交互弱于 plotly 原生全功能；
- **移动端**：未做专门适配，小屏体验一般；
- **标注词表**：A4 标注层是规则词表不是 LLM 理解，长尾事件会「分不出」（此时如实 unavailable，不硬分）。

## 三、结论

对标结论：**在「让用户放心」这个维度上，自研组件的优势不是功能更多，而是契约更硬**——A 股语义不反转、数据不编造、成本要披露、滞后要亮牌、风险要排雷，且每条契约都有守卫测试钉住（mutation 验证非假绿）。功能广度上市面成熟组件仍有可借鉴处，已在 `docs/algorithm_benchmark.md` 采纳清单中按「价值/成本」逐项吸收（R1-R6/R9/R10 已落地）。
