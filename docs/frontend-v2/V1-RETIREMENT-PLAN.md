## 4. v2 的能力边界（诚实红线，不可逾越）

- **真实券商下单**：仅 `43_实盘交易`（v1）。v2 的 `TradingAccount` 只渲染只读账户概览，明确不提供任何交易/下单能力。
- **只读端点**：`DataSourceView` / `DataExport` 等只查不写（纯前端导出原始 JSON，无写能力）。
- **未接入功能不造假**：验证码登录 / 注册、跨股财报筛选器等 v2 未接入的能力——页面如实标注"不可用 / 未接入"，不摆假按钮。
- **实时源依赖**：行情依赖 akshare，联网不可用时代码优雅降级（显 `—` / 空态），不编造数字。

## 5. 退役路线图（分阶段，按需推进）

### Phase A — 已完结（2026-11-09 ~ 11-13）
- v2 技术栈审计 + 功能对齐（63 native）。
- 组件级测试治理 §33–§40 收官（672 passed / 1 skipped，98 文件，**业务代码零改动、零真缺陷**）。
- 生产构建 smoke 跑通（950ms，主包 gzip 85 kB）。

### Phase B — 建议（非强制，低成本）
- **v1 进入"冻结 / 只读兜底"模式**：不再新增任何 v1 页（技术栈红线已禁）；11 个 pinned 保留访问，10 个非核心 pinned 在功能全景页标注"实验性 / 低频，可能随 v1 退役"。
- **`43_实盘交易`**：维持 v1 真实下单，v2 只读概览；若要把交易带进 v2，需单独的合规评估（超出当前红线，不建议）。

### Phase C — 未来可选（高成本，待评估）
- 若 v1 基础设施（Streamlit server / akshare 定时任务）维护成本过高：把 10 个非核心 pinned 中的可替代项（如 `13_市场强弱`）迁移到 v2 只读聚合，其余直接下架。
- 目标终态：**v2 全面取代 v1 只读浏览，v1 仅保留 `43_实盘交易` 一个进程**。

## 6. 风险与回滚

- **风险 1：双前端维护成本**。缓解：功能全景页清晰标注 `native / pinned / v1-only`；深链兼容重定向 `/legacy`；v2 新增页优先。
- **风险 2：用户入口混淆**。缓解：导航仅暴露 v2 入口，pinned 页通过功能全景的 v1 直达链接访问，不进主导航。
- **回滚**：v2 若出现故障，v1 仍可独立运行（独立 Streamlit server + 独立数据源），无需回滚 v1；反之亦然。双前端互为兜底，是健壮性而非负担。
