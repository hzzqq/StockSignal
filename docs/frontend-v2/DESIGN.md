# StockSignal 前端 V2 · 视觉与数据可视化规范（DESIGN）

> 配套 `PLAN.md` §5 数据语义红线。本文件所有色值取自真扫 `modules/ui_theme.py:29-41` 并给出升级方案，不凭空设计。
> 阶段：规划，不写码。

---

## 1. 视觉定位 ·「好上加好」的 4 条可评判主张

| # | 主张 | 怎么算做到（可测） |
|---|---|---|
| 1 | **决策优先，不是图表堆砌** | 任何页面首屏第一屏内必须出现「当前结论 + 数据日 + 置信/降权状态」；`PLAN.md` §8 用 Playwright 断言首屏 DOM 顺序 |
| 2 | **数据可信度可见** | 数据日、新鲜度封顶、事件因子失效原因全部**可见**；陈旧数据与新鲜数据一眼可分（虚线/灰化/角标），不允许旧数据伪装新鲜 |
| 3 | **单一视觉语言，消灭页面漂移** | 74 页统一由 `tokens.css` + `shared/ui` 供给；新增页不得自带页面级 CSS 覆盖色板。用 CSS 扫描守卫检查硬编码 hex 数量趋零 |
| 4 | **切页不中断** | 客户端路由取代 Streamlit 整页 rerun；图表/表格滚动位置与筛选态在切页后可恢复 |

### 2.1 色板：沿用真值 + 语义化升级

现有真值（`modules/ui_theme.py`）：

| 变量 | 真值 | 语义 |
|---|---|---|
| `UP` | `#ff4d4f` | 涨（红） |
| `DOWN` | `#00d486` | 跌（绿） |
| `HOLD` | `#ffa502` | 观望（橙） |
| `SF_BG` | `#0f0f23` | 页面底 |
| `SF_CARD` | `#1a1a2e` | 卡片 |
| `SF_CARD_DARK` | `#15152a` | 卡片深 |
| `SF_TXT` | `#e2e8f0` | 主文本 |
| `SF_BORDER` | `#2d2d44` | 边框 |
| `SF_GRID` | `#23233c` | 网格线 |

**V2 升级点**（不改业务语义，只补结构）：

```
/* 基底 —— 暗色（默认） */
--bg-base:      #0f0f23;  --bg-surface:  #1a1a2e;  --bg-raised:   #20203a;
--bg-sunken:    #15152a;  --border:      #2d2d44;  --grid:        #23233c;
--text-1:       #e2e8f0;  --text-2:      #94a3b8;  --text-3:      #64748b;
--brand-1:      #4f46e5;  /* 沿用 ui_theme.py:79 primaryColor */

/* 语义 —— 价格域（两套，见 §3） */
--ss-up:  #ff4d4f;  --ss-down: #00d486;   /* 全站/交易屏：红涨绿跌 */
--doc-up: #009e60;  --doc-down:#e5484d;   /* 报告体/个股页例外：绿涨红跌 */

/* 语义 —— 非价格 */
--signal-strong: #ff4d4f;  --signal-weak: #00d486;  /* 强弱信号灯，必须配 ▲/▼ 形状 */
--warn:  #ffa502;  --info: #4f46e5;  --danger:#e5484d;
--stale: #64748b;  /* 陈旧/降权专用灰 */

/* 亮色主题（swiss / ink 对应） */
--bg-base:#ffffff; --bg-surface:#f4f6fb; --text-1:#1e293b;
```

**主题模式**：`finpro / terminal / aurora / cyber → dark`，`swiss / ink → light`（沿用 `ui_theme.py:106` 强制规则）。V2 用 `data-theme` 属性 + Tailwind CSS variables 切换，不复制两套组件。

### 2.2 字体与刻度

| 项 | 值 |
|---|---|
| 中文栈 | `system-ui, -apple-system, "PingFang SC", "Microsoft YaHei", "Noto Sans SC", sans-serif` |
| 数字/金额 | 等宽表格数字 `font-variant-numeric: tabular-nums`；K线/表格必开，防跳动 |
| 字号刻度 | 12 / 13 / 14 / 16 / 20 / 26 / 34 px（对应 caption → body → h3 → h2 → h1 → hero） |
| 间距刻度 | 4 / 8 / 12 / 16 / 20 / 24 / 32 / 48 px（4px 基准） |
| 圆角 | 卡 12px、按钮 8px、chip 999px、小控件 6px |
| 阴影 | 暗色下**不用大投影**（现有真实实现就是无阴影卡片 + 边框），hover 用 `translateY(-2px)` + 品牌色描边 |
| 动效 | hover/展开 160ms、页面转场 200ms、图表入场 ≤300ms；`prefers-reduced-motion: reduce` 全部降为 0 |

## 3. ⚠️ 双套涨跌色适用边界（P0，必须写进组件 API）

| 场景 | 变量 | 涨 | 跌 | 依据 |
|---|---|---|---|---|
| 全站 KPI、交易屏、行情看板、涨跌家数、实时榜、热度条 | `--ss-up/--ss-down` | **红** `#ff4d4f` | **绿** `#00d486` | A股惯例，`ui_theme.py:29-30` |
| 报告体、个股页**价格域**、研报式文档导出 | `--doc-up/--doc-down` | **绿** `#009e60` | **红** `#e5484d` | 项目 `test_colors.py` 硬锁的例外 |
| 强弱信号灯（🟢强势/🔴偏弱已判缺陷） | 形状 **▲/▼** + `--signal-*` | — | — | 与价格域是**两套语义**，靠形状区分，不得用颜色单独表达 |
| 陈旧/降权数据 | `--stale` | — | — | 灰化 + 虚线 + 「滞后 N 天」角标 |

**组件 API 强制**：所有显示涨跌的组件必须显式传 `priceDomain="market" | "report"`，**不设默认值**——缺省即编译报错。这样从类型层面杜绝「一刀切」和静默误用。

## 4. 布局语言 · Bento 网格

| 档位 | 断点 | 列数 | 说明 |
|---|---|---|---|
| Desktop XL | ≥1600px | 12 列 | 决策面板 + 侧栏 + 归因三栏 |
| Desktop | 1200–1599px | 12 列 | 主内容 9 列 + 侧栏 3 列 |
| Laptop | 900–1199px | 8 列 | 侧栏收为抽屉 |
| Tablet | 600–899px | 4 列 | 卡片 2 列 |
| Mobile | <600px | 1 列 | 决策结论置顶，图表降级为摘要卡 |

- `gap: 16px`，卡内 `padding: 16~20px`；卡高由内容决定，**禁止等高拉伸导致大片空白**。
- 页面骨架：顶栏（品牌/全局搜索/通知/主题/用户）56px → 侧栏 240px（可折叠 64px）→ 内容区（页标题 + 数据日条 + Bento 区）→ 回到顶部圆钮（沿用现有 40px 圆形、`right:24px;bottom:28px`、阈值 120 的约定）。
- **数据日条**是每个数据页的必备首行元素：显示权威数据日 + 新鲜度状态（正常/降权/陈旧），不是 `now()`。

## 5. 组件视觉规范

| 组件 | 尺寸/结构 | 状态 |
|---|---|---|
| KPI 卡 | 最小 180×96，标签 12px `--text-2` + 数值 26px 等宽 + meta 12px | 加载骨架 / 无数据（显示「无数据」而非 0）/ 降权（灰色角标） |
| 决策卡 | 结论 20px 加粗 + 仓位大数 + 归因贡献条 + 数据日 | 必须展示 `contributions`；`overall_promo=None` 时**不显示**该项，不填 0 |
| 数据表格 | 行高 40px，数字列右对齐+等宽，斑马纹用 `--bg-sunken` | 空/错/加载/降权四态；涨跌单元格按 `priceDomain` 取色 |
| 图表容器 | 最小 280×180，标题 + 数据日角标 + 图例 + 图表体 | `ResizeObserver` 重绘；容器过小时降级为摘要 |
| chip/标签 | 高 22px，圆角 999px | HOT/NEW 必须**附在带名称的条目内部**，禁止悬空标签（原版已修过此缺陷） |
| 按钮 | 主 36px / 次 32px | hover 品牌描边；危险操作二次确认 |
| 降权标记 | 角标 12px + 虚线边框 + `--stale` 灰 | 「滞后 N 天（≥8，陈旧）」等**按真实分类动态拼**，禁止泛化串 |

### 6.1 图表库选型与 bundle 预算

**主库 Apache ECharts**（153–173 KiB，TanStack 官方 2026-08 受控对比基线）—— 理由：K线、热力图、桑基、雷达、箱线、treemap 等 14 类场景**一个库全覆盖**，避免多库主题/取色/事件模型分裂。必须**按需引入**图表类型与组件，`echarts/core` + 显式 `use()`，不吃全量包。

**补充库 Lightweight Charts（未采纳）**：规划阶段曾评估 `~60 KiB gzip` 的专业 K线屏补充库（candles/十字准星/缩放体验优于通用库），但当前实现**未引入**——`frontend-v2/package.json` 仅依赖 `echarts ^6.1.0`，个股 K线由 ECharts 的 `candlestick` 图表类型实现（见 `src/features/stock/charts/KLineChart.tsx`）。后续若要切换，须先在 `package.json` 落地依赖再回改此段，避免文档与代码脱节。

**不选**：Recharts（153–168 KiB 但高级图表类型缺，K线要自己造）；Highcharts / FusionCharts（商用授权）；TanStack Charts（36–42 KiB 很轻但需自管状态、金融图表能力需自建，不适合本项目密度）。

| 预算 | 上限 |
|---|---|
| 首屏 JS（gzip） | ≤ 200 KiB |
| 单图表页增量 | ≤ 180 KiB |
| 图表库按需 chunk | ECharts 核心 + 本页图表类型 |

> ⚠️ 上述体积是 **2026-08 TanStack 官方受控对比基线**，不是跨机器性能排行，实施前需用本项目真实数据复测。

### 6.2 图表视觉规范

- 网格线 `--grid`，零线 `--border`，文本 `--text-2`；暗色下不用纯黑/纯白。
- tooltip 用 `--bg-raised` 卡 + `--border` 边框，数字等宽，中文单位。
- K线阴阳线：**按 `priceDomain` 注入**，报告体页面不得沿用交易屏红涨绿跌。
- 事件催化点：竖虚线 + 顶部标签；**降权区间**：`--stale` 半透明遮罩 + 「滞后 N 天」标注。
- 动画 ≤300ms；`prefers-reduced-motion` 下关闭入场动画（数据正确性不依赖动画）。
- **禁止截断 Y 轴造成视觉误导**；对数轴必须显式标注。

## 7. 状态呈现（诚实红线的落地形态）

| 状态 | 呈现 | 禁止 |
|---|---|---|
| 加载 | 骨架屏，保留真实布局尺寸 | 用假数据占位 |
| 无数据 | 「无数据」+ 说明文案 + 重试入口 | 显示 0 / `—` / 插值 |
| 错误 | 中文错误文案（沿用后端信封 `message`）+ 重试 | 静默吞异常、空白卡 |
| 降权 | 虚线边框 + 灰化 + 「滞后 N 天（≥8，陈旧）」真实分类角标 | 硬编码「已降权/停更」泛化串 |
| 部分缺失 | 只渲染有数据的字段，其余标「无数据」 | 补零凑齐图表 |

## 8. 可访问性

- 涨跌**不得只靠颜色**：配 ▲/▼ 形状、数值符号 `+/-`、屏幕阅读器文本「涨 2.3%」。
- 图表旁提供**可展开的数据表**作为等价文本替代。
- 键盘：侧栏/图表 tooltip/下拉/对话框可完整走查，焦点可见（品牌色 2px outline）。
- 对比度：正文 ≥4.5:1，大字 ≥3:1；`--text-3` 仅用于非必要辅助文字。
- 动效可关闭；`aria-live` 用于刷新结果与告警。

## 9. 禁止事项清单

1. ❌ 用颜色单独表达涨跌或强弱（必须形状/符号双编码）
2. ❌ 把 `--ss-up/--ss-down` 一刀切套到报告体/个股页价格域
3. ❌ 悬空的 HOT/NEW 标签（必须内嵌在带名称条目里）
4. ❌ 无数据补 0、插值、造占位数字
5. ❌ 陈旧数据不带可见降权标记
6. ❌ 页面级硬编码 hex 覆盖色板
7. ❌ 截断 Y 轴 / 不标注对数轴 / 用动画暗示数据确定性
8. ❌ 前端复制 `derive_position` 或新鲜度封顶规则
9. ❌ 硬编码「已降权/停更」等泛化故障文案
10. ❌ 图表库全量打进主包
