## 3. 体检维度与语义

### 3.1 结构体检（红灯 = 阻断）
- 文件存在 / JSON 可解析 / 顶层为对象
- 必备字段：`model / latest_date / horizon / top_long / top_short / daily`
- `latest_date` 合法 ISO 日期
- `top_long` / `top_short` 非空列表，每条含 `symbol/pred/rank`
- symbol 格式：`sh/sz/bj + 6 位数字`
- rank 排序：看多榜非增（1.0 最强在前）、看空榜非降（最小 = 最强看空）

### 3.2 新鲜度 SLA（红灯 = 阻断）
`age = max((today - latest_date).days, 0)`，按模型阈值（默认，可 `--max-age k=v` 覆盖）：

| 模型 | SLA（自然日） | 说明 |
|---|---|---|
| baseline / ev / gru / ens | 8 | 覆盖周末（周五生成 → 周一查仍绿） |
| fusion | 8 | 当前真实滞后 20 天 → 红灯，暴露数据源停更 |

### 3.3 ens↔baseline 对齐守望（黄灯 = 登记不阻断）
`Jaccard(ens.top_long[:20], baseline.top_long[:20])` ≥ 0.75 → 绿（降权语义成立）；
低于阈值 → 黄灯 + 提示「需 sj 侧核对 gru 权重是否回归 / z 序口径 / 数据版本错位」。
黄灯不改变退出码。

## 4. 使用方式

```bash
# 全量体检（Markdown 报告；红灯 → 退出码 1）
python scripts/p1_signal_quality_report.py

# 指定目录 / JSON 输出 / 覆盖阈值 / 心跳参数
python scripts/p1_signal_quality_report.py --dir data/p1_signals --json
python scripts/p1_signal_quality_report.py --max-age fusion=25 --max-age ens=3
python scripts/p1_signal_quality_report.py --heartbeat-max-idle 4 --no-heartbeat
```

- 或并入现有推送链尾部环节（S13 之后追加体检步骤）。

## 5. 已知缺口与待办（黄灯/红灯根源，需 sj 侧或数据侧处理）

1. **fusion 数据源停更（红灯）**：fusion latest=2026-10-12，滞后 20 天。需确认 sj 侧
   fusion 预测链（输入因子/模型）为何停在 10-12，修复后重推。
2. **ens 命名/内容语义（黄灯）**：文件名与 `model` 字段仍为 `ens_v39gru_w025`（w=0.25），
   与「降权 w=0 落地」语义不一致；且 ens 榜与 baseline 榜 Jaccard 仅 0.652——若 w=0 纯 v39
   成立，z 序与概率序在单日截面单调等价，榜应高重叠。需 sj 侧核对：
   - 导出脚本是否硬编码 w=0.25（37 脚本改 W_GRU 后导出链未同步）；
   - ens z 序是否跨日归一（跨日 z 与单日概率序天然不完全等价，属口径差异则登记豁免阈值）。
3. **推送链 SLA（v2 已纳入体检）**：heartbeat 10-31 最后心跳距今 1 天（SLA 3 天内 → 绿），
   但完整推送链仍未每日跑（10-12→10-26→10-31 间隔不均）。体检已能暴露停更；
   若希望「工作日必须跑」需改为交易日感知 SLA（按日历排除周末/节假日）。

## 4.5 深挖结论（2026-11-01~02，B 项：fusion 停更 / ens 命名语义）

| 疑点 | 结论 | 依据 |
|---|---|---|
| fusion latest 停在 10-12（滞后 20 天） | **设计性滞后，非事故**：fusion 依赖 y_excess 前瞻标签，latest_date 天然落后四路约一个 h10 窗口+标签确认期 | sj 推送链 `zz_daily_push.sh` S11 注释（T-352）：「fusion 依赖 y_excess 前瞻标签，latest_date 设计性滞后于四路，不要求一致」 |
| ens 文件名 w025 是否仍含 gru 权重 | **w=0 已落地，w025 仅为兼容名**（ks `gen_morning_event_sentiment.py` 硬编码引用不变） | sj `ens降权生产变更说明_2026-11-01.md` + 37 脚本 docstring + `--w-gru` 默认 0.00 |
| ens 是否残留 gru 信号（parquet 级） | **无残留**：ens pred=当日截面 z_v39，与 baseline v39 pred 单日截面单调等价，同日 top20 **Jaccard=1.0** | 实测 `pred_ens_v39gru_w025_h10.parquet` vs `pred_baseline_h10_v39.parquet`（2026-10-26） |
| 黄灯 Jaccard=0.652 根因 | **baseline json 生成源与 ens 源模型版本不一致**：baseline json ← `pred_baseline_h10.parquet`，ens ← `pred_baseline_h10_v39.parquet`；两文件同日 pred 值不同（600212：0.0199 vs 0.0392），top20 Jaccard=0.667 | 实测两 parquet + json top 榜溯源 |

**给 sj 侧的核对建议**：
1. 确认 `pred_baseline_h10.parquet`（baseline json 生成源）是哪个模型版本（疑似非 v39 / 旧版）；
2. 若生产口径为 v39，baseline json 应改由 `pred_baseline_h10_v39.parquet` 导出（06_export_signal.py 输入统一），消除页面 baseline 榜与 ens 榜口径分裂；
3. 融合体检修正：fusion SLA 已放宽至 30 天（模块常量），避免设计性滞后误报红灯。
