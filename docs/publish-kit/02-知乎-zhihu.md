## 标题

一个人全栈做 A 股分析工具：我踩过的坑和拿到的东西

## 正文（从下一行开始复制）

> 声明：本文是我个人项目的经验分享，所有代码开源，不构成任何投资建议。

最近把我一个人从 0 到 1 做的 A 股事件驱动分析平台开源了（GitHub 链接在文末），趁热写写过程中最值得说的三个设计决策，给同样想做量化/金融工具的人一点参考。

**决策 1：数据源必须多路降级**

做金融数据工具第一天就会遇到：AKShare 某个接口挂了，整个项目就瘫了。我的解法是 4 级降级链——AKShare → BaoStock → 新浪 → 东方财富，最后还有本地 SQLite 缓存兜底。单点故障不崩，断网也能看历史。后来还接入了腾讯自选股 MCP 作为补充数据源（行情/资金流/财报），结论是：标准数据用 API，定制逻辑自己写，混合模式最稳。

**决策 2：测试要验"数据对不对"，而不是"页面崩没崩"**

一开始我也写了大量"页面能跑起来"的冒烟测试，后来发现这是安慰剂——页面不崩不等于数据对。现在项目有 1767 个自动化测试，其中最关键的是数据正确性断言：OHLC 自洽（high 必须 ≥ max(open,close)）、日期严格单调、股息率反推公式落在合理区间。这类断言比 100 个冒烟测试有用得多，它们真的抓出过乱序 K 线导致技术指标错位的 bug。

**决策 3：A 股 UI 的细节是真实用户习惯**

A 股红涨绿跌（和美股相反）、利空事件标在 K 线下方、K 线支持日/周/月切换 + 双击弹分时——这些看起来小，但都是真实使用场景里被反复验证的需求。暗夜/白天双主题也做了，毕竟盯盘时间往往在晚上。
