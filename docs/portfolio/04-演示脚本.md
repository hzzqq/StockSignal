# 04 · 演示脚本（本地跑起来 + 5 个演示场景）

> 每个场景都可在本地复现。演示前先按下面"环境准备"跑通一次。

## 环境准备（首次，5~10 分钟）

```bash
# 1) 克隆 + 建虚拟环境
git clone https://github.com/hzzqq/StockSignal.git
cd StockSignal
python -m venv venv
venv\Scripts\activate          # Windows；macOS/Linux: source venv/bin/activate

# 2) 依赖（前端 + 后端两处）
pip install -r requirements.txt
pip install -r backend/requirements.txt
cd frontend-v2 && npm install && cd ..

# 3) 初始化数据库（建表 + admin/demo 种子账号）
python -m backend.scripts.init_db
```

## 一键启动

```bash
# Windows：双击 启动StockSignal.bat
#   自动检查 Python → 初始化数据库 → 起后端(5050) + 前端(8899) → 开浏览器
# macOS/Linux：按 README「方式 B 手动分步」，终端1 起 Flask、终端2 起 Streamlit
```

登录：`admin / Admin@123` 或 `demo / Demo@123`。

> v2 前端另有独立链路：双击 `start_frontend_v2.bat`（后端 5050 + Vite 5173，隐藏窗口常驻）。
> 停止用 `_stop_services.bat`。演示 v2 时走这条。

## 场景 1：决策闭环的"可解释"（30 秒，最有讲头）

1. 打开 v1 **决策可解释归因**页（导航「决策与风控」→ 第 54 页）。
2. 选一个有数据的日期，看仓位建议 **5%~95%** 与逐条 `reasons`。
3. 指着归因面板讲："每个输入维度（温度/方向/周期/晋级率/事件）贡献多少仓位变化都列出来了，
   不是黑箱打分——这是 `derive_position(explain=True)` 的输出。"
4. 切到一个**数据旧**的日期，观察仓位被新鲜度守卫自动压低——"宁可保守不误导"。

## 场景 2：数据降级韧性（30 秒）

1. 打开 **数据源与接口检测** 页，看当前主源与各备用源健康状态。
2. 拔网线/断代理（或把主源配置成不可达），刷新任一数据页。
3. 观察自动切到备用源、页面不崩——"单点故障不影响可用性"。

## 场景 3：K 线交互与 A 股配色（20 秒）

1. 行情看板或个股分析，切日/周/月 K。
2. 十字光标悬停、双击弹分时。
3. 强调：**涨红跌绿**（A 股惯例）；夜间/白天双主题一键切换。

## 场景 4：回测与成本模型（30 秒）

1. 打开策略回测页，跑一个默认策略。
2. 对照 A/B 成本模型曲线——摩擦成本约 **3.99 个百分点**（README 已公开的数字）。
3. 讲："回测不是画好看的曲线，真实交易成本必须计入，否则全是幻觉。"

## 场景 5：v1→v2 分类清单（20 秒，展示工程判断力）

1. 打开 v2 功能全景页（`/catalog`），看四档状态徽标：
   **native 65 / v1-pinned 9**。
2. 讲："每个功能页我都标了承接状态——真迁移的、只保留 v1 直达的、
   永久不迁的（实盘交易）。迁移不是目的，能力对等且风险可控才是。"
