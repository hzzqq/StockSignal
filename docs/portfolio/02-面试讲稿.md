## 3 分钟版（适合自我介绍后的"介绍一个项目"）

**① 定位（20 秒）**
"StockSignal 是我独立开发的 A 股事件驱动投研平台。它不是荐股工具，核心是回答一个问题：
**怎么把温度、方向、周期、晋级率、事件催化这些模糊判断，变成一个可解释、可回溯的仓位数字。**"

**② 架构（40 秒）**
"工程上是四层：前端、Flask 工厂后端、56 个不依赖 UI 的逻辑模块、SQLite 数据层。
前端现在是双栈并存——v1 Streamlit 74 页转只读，v2 React 19 生产前端承接 65 页。
我给 v1/v2 做了四档分类清单，明确哪些真承接、哪些永久留 v1，避免'为了迁移而迁移'。"

**③ 核心创新（60 秒）**
"决策闭环收敛到一个函数 `derive_position`：四维输入算出 5%~95% 仓位，逐条输出理由。
三个关键设计：
- **新鲜度守卫**：数据日不是用今天，而是取数据源的权威日期，滞后 4 天封顶 60%、8 天封顶 40%——宁可保守也不误导。
- **刻度校准**：用历史回测反推建议幅度，但有界 ±5、样本小于 8 不出建议、只建议不自动写文件。
- **每日对账**：预测落盘，次日自动比对，形成可验证闭环。"

**④ 结果（30 秒）**
"规模上 74 页、158 个 REST 端点、4760 个自动化测试，双主题真浏览器审计 138/138 通过。
回测方向命中率 **49.1%**——我主动说清楚：接近随机，这个机制证明的是闭环自洽，不是有显著 alpha。
这也是我刻意保留的诚实口径，不拿小样本吹效果。"

**⑤ 收尾（30 秒）**
"从这个项目我最大的收获是：**工程价值不只在功能跑通，更在于让系统在数据缺失、样本不足时依然诚实。**
所以我写的不只是业务代码，还有一整套 AST 守卫测试——专抓'能跑但语义错'的静默 bug。"

## 5 分钟版（适合技术深挖 / 项目面）

在上面 3 分钟基础上，展开三段：

**A. 数据层韧性（+50 秒）**
"取数是 4 级降级链：AKShare → BaoStock → 新浪 → 东方财富 → 本地缓存。
关键不是'能降级'，而是并发不拖垮数据源：共享有界线程池 + `fetch_many` 统一并发，
每个源 10 秒超时、12 秒调用上限。缓存层做过 200 请求压测，L0 命中率 79.5%（reports/cache_layer_eval.json）。"

**B. 生成物诚实性守卫（+50 秒）**
"这类 bug 最阴：图表拿到了空 DataFrame，渲染出来是个空表，测试全绿但用户被骗。
我的做法是 AST 静态守卫——分析被调函数真正读了哪些键/列，跟调用方实际喂的数据比对，
取数不足就跳过不产出。还有一条硬规矩：`pytest.skip` 只允许'环境不具备'，
'数据疑似被覆盖/样本异常'必须 fail——否则守卫会在故障真发生时自我静音。"

**C. 渐进式重构决策（+50 秒）**
"v1→v2 不是重写，是四档分类：native 真承接、data 只展示、v1-pinned 保留直达、v1-only 永久留 v1。
实盘交易端点属于 v1-only，永久不迁——这是产品红线不是技术无能。
守_FLAGS 测试锁死分类一致性。代价是双栈维护成本，所以我定下'禁新增 Streamlit 功能'的规矩。"

## 预判追问（准备诚实答法，别硬编）

| 追问 | 你的答法（要点） |
|---|---|
| 49.1% 命中率是不是说明没用？ | 是的，作为预测它接近随机。我的贡献是把决策过程变得**可解释、可审计、可自纠偏**，命中率是诚实记录而非卖点。论文 7.2 也如实写了纵向样本偏少。 |
| 为什么用 SQLite 不用 PostgreSQL？ | 个人投资者单机场景，SQLite 零运维、文件级归档天然适配每日快照。代价是并发写入受限——所以我用独立库跑回归测试避免锁冲突，这是真实踩过的坑。 |
| 双前端为什么不全部迁 React？ | 实盘交易端点有真实券商下单能力，属高风险区，永久留 v1；其余按价值分级迁移。全量重写风险收益不划算。 |
| 测试 4760 个会不会太多/太慢？ | 分层：功能单测快，冒烟用离线缓存，全量重跑才跑真浏览器审计。守卫测试是AST级的，不依赖运行环境。 |
| 有没有上线/真实用户？ | 有本地多用户体系（admin/demo）和 10000 虚拟用户并发模拟，但定位是个人投研工具 + 毕设作品，没有对外运营的真实用户增长数据。 |
| 决策闭环能不能实盘？ | **不能**，项目明确无券商下单，v2 零交易路径。这是有意的产品边界。 |
| P1 信号数据停在 10-16 是不是 bug？ | 是数据新鲜度问题，不是代码缺失。新数据集已导出，fusion 层的设计性滞后；超 8 天会触发仓位封顶 40%，系统如实提示而非假装数据新鲜。 |
