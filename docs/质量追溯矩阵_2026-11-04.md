| 模块 | 页面源码的 `import` | AST 解析 `from modules.X import …`，不执行代码 |
| 测试 | `tests/` + `backend/tests/` + `modules/tests` | 测试文件 `import` 到该模块即计入「已覆盖」 |
| 实证 | `reports/*.json` | 扫描全仓文本，找出读写该产物的脚本/模块/论文素材 |

「覆盖」只表示**有测试文件引用该模块**，不代表分支覆盖充分；分支覆盖以覆盖率门禁（`--cov-fail-under`）为准，两者互补而非替代。

## 六、复跑与限制

```bash
python scripts/gen_trace_matrix.py            # 重新生成本表
python scripts/gen_trace_matrix.py --dry-run  # 只打印摘要，不写盘
```

已知限制：

1. 只做**静态 import 追溯**，不做运行时插桩——「测试文件 import 了该模块」不等于该模块每条分支都被断言过。
2. 功能域按页面编号段归组，编号本身即产品设计的一部分；新增页面落在已有编号段会自动归入对应域。
3. `reports/*.json` 若由外部交接放入（代码里无引用），本表会显式标红「无代码引用」，不做粉饰。
