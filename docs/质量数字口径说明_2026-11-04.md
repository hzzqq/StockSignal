## 一、两种口径：为什么同一份代码会数出 4394 和 5086

| 口径 | 做法 | 数出来的是什么 | 典型数字 |
| --- | --- | --- | ---: |
| **A. 静态定义口径** | 用 `ast` 解析测试源码，数 `def test_*` 函数定义 | 写了多少个测试**函数** | 论文第 6 章 4,394 |
| **B. 收集口径** | `pytest --collect-only` 实际收集 | 答辩评委/CI 实际会跑多少个**用例** | README 4,979 → 现 5,086 |

关系恒定：**B = A + 参数化展开项**。
一个 `@pytest.mark.parametrize` 带 5 组参数，源码里仍是 1 个 `def test_*`，但 pytest 会展开成 5 个用例。
因此 B 必然大于 A，且差额可以逐项解释（本次差额见下表「A→B 展开增量」）。

两种口径都是对的，错的是**引用时不说口径**。论文若被问「你说 4394，我实测 5086」，正确回答是：
「4394 是静态函数口径的历史快照，5086 是参数化展开后的收集口径；两者差值为参数化用例数，同一次提交内可复现。」

**用两组时点的实测把这个关系钉死（2026-11-04）**：

| 时点 | 静态口径 A | 收集口径 B | 差额 B−A |
| --- | ---: | ---: | ---: |
| 论文 / README 历史快照 | 4,394 | 5,086（README 4,979 更早） | **692** |
| 本次实测 | 4,348 | 5,133 | **785** |

两个时点的差额都在 700 量级——**说明 4394↔5086 之间差的不是「两套代码」，而是同一批参数化用例的展开**。
A 从 4,394 变到 4,348 是时点差异（合并/重构会删测试函数），与口径无关；两者都被脚本逐项可复算。

### 端点数为什么必须写「运行时口径」

`89` 是早期静态计数快照，已无法复现；`35`（报告口径）只数了 `backend/api/` 下的 route 装饰器，漏了
`backend/auth/`、`backend/app.py` 等处的路由，两者都不可用于答辩。

唯一可复核的口径是**运行时注册表**：

```bash
# 在仓库根目录执行（需已装依赖；禁用后台调度线程避免副作用）
python -c "from backend.app import create_app; app=create_app(); print(len([r for r in app.url_map.iter_rules() if r.endpoint!='static']))"
```

本次实测：**92** 条 Flask 规则（15 个 Blueprint：admin/alert/auth/chat/config/dashboard/forum/market/
market_alert/recommendations/research_run/stock_tags/stocks/tasks/trade），加上 `backend_fastapi/` 的 **9** 个
FastAPI 端点，合计 **101**。静态装饰器计数（`scripts/quality_metrics.py`）与运行时 `url_map` 一致，
说明「92」是唯一自洽的 Flask 口径。

## 五、答辩问答模板（三问三答）

**Q1「论文写 4394 个测试，我这边跑出来 5086，哪个是真的？」**
「两个都是真的，是口径不同。4394 是静态函数口径的历史快照——数的是源码里 `def test_*` 的个数；
5086 是收集口径——pytest 会把 `parametrize` 展开，一个函数变成多组用例。同一次提交内两者差额
就是参数化用例数，用一条命令可以同时打印两个数。」

**Q2「89 个 REST 端点是怎么数的？为什么有人数出 35 个？」**
「89 是早期静态计数的过期快照，已无法复现，我不再用它。35 只数了 backend/api 目录，漏了 auth 与
app 主文件。可复核的口径只有一个：运行时 `app.url_map` 的非 static 规则数，当前 92 条（15 个 Blueprint），
再加 FastAPI 的 9 个端点共 101。」

**Q3「这些数字怎么保证不是编的？」**
「`scripts/quality_metrics.py` 一条命令复跑全部数字；`tests/test_quality_numbers_sync.py` 把文档里的数字
钉在两处——规模类对同批快照（快照自带生成时点与基线 commit），结构类对实时实测值。文档一旦过期，
测试立刻红。数字不是我写在文档里的结论，是测试守着的产物。」

## 六、复跑方式与已知限制

```bash
# 全量口径（含 pytest 收集，约 15 秒；收集期会拉起 conftest，需离线环境）
python scripts/quality_metrics.py

# 仅静态口径（秒出，适合 CI/守卫测试）
python scripts/quality_metrics.py --fast

# 回填本文档数字块，并同步生成守卫用的快照（两件事必须一起做）
python scripts/quality_metrics.py --fast \
    --write docs/质量数字口径说明_2026-11-04.md \
    --snapshot docs/quality_metrics_snapshot.json

# 落盘机器可读结果，供论文图表/答辩 PPT 引用
python scripts/quality_metrics.py --json docs/quality_metrics.json
```

已知限制（如实记录，不隐藏）：

1. 「收集口径」依赖 pytest 收集成功；收集失败时脚本输出 `—` 而不猜数，且不参与守卫测试断言。
2. 规模类数字由脚本回填并与快照（含时点/commit）绑定，结构类数字直接对实时值；手改文档数字会被守卫测试判红。
   对外引用规模类数字时，务必连同快照时点一起说，否则又回到「拿旧数字当现状」。
3. 独立复刻一份 worktree 时，`data/`（运行数据，被 git 忽略）不随仓库带出，个别依赖本地数据的用例会失败；
   这不影响本文档的代码规模统计（`data/` 本就在排除口径内），但跑全量测试前需从主工作区同步 `data/`。
