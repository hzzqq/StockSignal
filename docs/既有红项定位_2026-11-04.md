## 逐项细节

### 1. page54 守卫取错了 if 节点（产品代码是对的）

实测（把守卫的 `_find_if_q` 与"按 `ef` 精确匹配"两种取法并排跑）：

```
guard 选中的 if 条件: _q        位于 line 551
目标 if 行号: 565            orelse 含提示: True
```

页面的真实结构是对的：`pages/54_今日决策面板.py:565` 是 `if ef.get("available"):`，无事件因子提示 `xc_info_banner(f"该标的无事件因子信号：...")` 在 `:603`，确实落在 565 的 `orelse` 内。红的是守卫：它先 `_find_if_q` 拿到 `if _q:`（551），再在其 body 内取"第一个 `*.get()` 的 If"，而 590 行的全球宏观 `if _mc.get("available"):` 先被命中，于是断言去检查宏观提示文案。

**最小补丁**（改守卫，不改页面）：把 `tests/test_page54_ev_query_guard.py:81-89` 的内层挑选换成按变量名精确匹配：

```python
inner = None
for n in ast.walk(if_q):
    if isinstance(n, ast.If) and isinstance(n.test, ast.Call) \
            and isinstance(n.test.func, ast.Attribute) and n.test.func.attr == "get" \
            and isinstance(n.test.func.value, ast.Name) and n.test.func.value.id == "ef":
        inner = n
```

改完该用例即转绿（已用 AST 探针验证 `orelse` 含关键字）。

### 2 / 3. 两条 session 用例断言了旧版 `query_params` 形状

`AppTest().query_params` 在当前 Streamlit 上是 `dict[str, str]`：`get("token")` 返回 `'tok-abc-123'`；用例仍按老版本 `dict[str, list[str]]` 写 `== ["tok-abc-123"]`。**产品行为正确**（token 已按预期回填/续期），只是断言形状过期。

补丁（两处同改）：

```python
# tests/test_session_login_sync.py:24
assert at.query_params.get("token") == "tok-abc-123"

# tests/test_session_refresh.py:84
assert at.query_params.get("token") == NEW_TOKEN
```

若要兼容新旧两版 Streamlit，可写成 `in ("tok-abc-123", ["tok-abc-123"])`，但不建议——把"兼容旧 API"固化进守卫会掩盖真实回归。

### 4. shepherd 镜像比 live 少尾部数据

| 文件 | 大小 | 差异 |
| --- | --- | --- |
| `data/shepherd_history.csv`（live） | 534,914 B | 含 `2026-11-02` 行 |
| `backups/shepherd_history_restored.csv`（镜像） | 529,920 B | 缺该行；另多处浮点末位精度不同 |

```text
At index 4804 diff: '...,24.49774426584793,...' != '...,24.497744265847935,...'
Left contains one more item: '2026-11-02,4653.0,813.0,...'
```

根因：镜像是某次数据恢复/迁移时的快照，之后 live CSV 继续追加与重算（浮点重算导致末位差），镜像没跟着更新。**属数据基线过期**，不是回填逻辑坏了。

两种处置（择一）：
- 重生成镜像：把 live CSV 复制为镜像（`Copy-Item data/shepherd_history.csv backups/shepherd_history_restored.csv -Force`），并确认这正是"restored"语义——若该文件应保留"恢复时的原始状态"，则改用下一种；
- 若镜像本就应保留历史快照，把断言降级为**结构性一致**：日期集合包含关系 + 列数一致 + 行数单调，不逐行逐字符比。

注意：`data/` 被 gitignore，镜像 `backups/` 入库；重生成镜像会产生一次数据提交，需单独审。

### 5. CSS 缓存参考副本过期（UI 变量化漏更）

- 源：`widgets.py:1036 _sidebar_nav_css()` 现输出 `border-radius:var(--ss-radius-sm)!important`（UI 变量化改造的**意图性变更**）。
- 冻结副本：`tests/test_static_css_cache.py:48-49` 仍写 `border-radius:8px!important`。

该守卫的协议是"零视觉回归"——参考副本只在**有意变更样式**时同步更新。本次 UI 变量化就是有意变更，漏更的是副本。

补丁：把 `tests/test_static_css_cache.py:48` 的 `border-radius:8px!important` 改为 `border-radius:var(--ss-radius-sm)!important`（其余字符不动），并在提交说明里写明"UI 变量化意图性变更，参考副本同步"。改前建议用 `python -m pytest tests\test_static_css_cache.py -vv` 逐字符 diff 确认只有这一处差异。

### 6. `task_routes.py:104` 被两套静默异常标准同时判

```python
    # ui_audit_exempt: except-pass timeline SQLite 兜底读取尽力而为：...
    except Exception:
        pass
```

- `tests/test_t239_bare_silent_audit.py`：认 `ui_audit_exempt` → **通过**。
- `backend/tests/test_no_silent_swallow.py`：只认 `logger.*` 留痕或窄捕获 → **判红**。

两者对同一行给出相反结论，属口径冲突。最小补丁（同时满足两套）：在 handler 内加一行日志，标注保留：

```python
    # ui_audit_exempt: except-pass timeline SQLite 兜底读取尽力而为
    except Exception:
        logger.debug("task timeline SQLite 兜底读取失败，按空列表返回（内存事件为主源）", exc_info=True)
```

改后 `test_t239_bare_silent_audit` 与 `test_no_silent_swallow` 同时绿；若担心 `exc_info=True` 噪音，用 `logger.debug(...)` 不带 `exc_info` 亦可。
