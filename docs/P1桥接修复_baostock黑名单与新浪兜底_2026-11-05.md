# P1 K 线桥接修复：baostock 黑名单与新浪兜底（2026-11-05）

## 故障定位

`scripts/18_bridge_kline.py` 连续多日日志满屏 `timed out` / `接收数据异常` / `FAIL`，
一度被归因为"网络抖动 / baostock 限流"。实测不是：

| 检查 | 结果 |
|---|---|
| `bs.login()` | `rc=10001011 黑名单用户，请与管理员联系`（连试 2 次一致） |
| `bs.query_history_k_data_plus` | 同一错误码，0 行 |
| 网络 | `baostock.com` 返回 200，无代理变量，WLAN 正常 |
| 时间点 | 11-02、11-03、11-04 三轮日志开头都还是 `login success!`，11-04 19:45 那轮之后被封 |

**结论：baostock 把我们这条出口 IP/账号拉黑（10001011），与网络、限流无关。**
11-04 那轮的 205 次 FAIL + 反复重登很可能就是诱因——原脚本 `bs.login()` **不校验返回值**，
黑名单后仍会闷头跑 1492 只、把 FAIL 打满日志。

## 脚本改动（`scripts/18_bridge_kline.py`，原文件备份 `18_bridge_kline.py.bak_20261105`）

1. **登录 fail-fast**：`bs.login()` 返回码非 0 时直接打印 `BAOSTOCK LOGIN FAIL rc/msg` 并退出；
   `--source baostock` 下退出码 2、**本轮不写任何数据**（避免继续给黑名单账号加压）。
2. **新增 `--source {auto,baostock,sina}`**：`auto`（默认）下 baostock 登录失败自动切新浪源
   （akshare `stock_zh_a_daily`，`adjust="qfq"`），**只补本地尾部、不动已有历史**。
3. **口径重叠校验**：追加前用同一交易日的收盘对比（本地 baostock 前复权 vs 新浪前复权），
   相对差 >1% 判 `basis_mismatch` → 该只**拒写**（除权/送股会让两套 qfq 基准差一个因子，
   拼接会在接缝处造出假跳空）。
4. 合并前把 `date` 统一成 `datetime64` 再去重排序：本地是 `datetime64[us]`、akshare 返回
   `datetime.date` 对象，混用会让 `drop_duplicates` 认不出"同一天"而写出重复行。
5. 基准沪深300 同步支持新浪口径（同样只补尾部，旧历史原样保留）。
